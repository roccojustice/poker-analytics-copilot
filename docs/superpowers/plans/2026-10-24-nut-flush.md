# Nut flush vs other flush Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Split the `Flush` hand type into `Nut flush` / `Other flush`, with a collapsible `Flush` group in the breakdown table and the `Hand` dropdown.

**Architecture:** `hand_strength.classify_hand` returns a leaf; a `HAND_GROUPS` mapping names `Flush` as their group. `spotlight._hand_split` emits a group row followed by leaf rows carrying `parent`. The page reads the same mapping from `spot-config` for the dropdown, the caret rows and the pick matching.

**Tech Stack:** Python 3, pandas, pytest; vanilla JS in `static/index.html`.

**Spec:** `docs/superpowers/specs/2026-10-24-nut-flush-design.md`

## Global Constraints

- Type names exactly `Nut flush`, `Other flush`; group name exactly `Flush`.
- `HAND_TYPES` order: `… "Full house", "Nut flush", "Other flush", "Straight", …` (replacing `Flush`).
- `hand_types` filter accepts leaves only; `Flush` → `SpotInputError` (unknown hand type).
- Inline comments: one line max (user's comment discipline).
- Strict red-then-green TDD for each behavior change.

## Review Focus

1. Hero holds two flush-suit cards, only the lower would be nut (e.g. `Kh2h` on `Ah9h4h`): the **highest** suited hole card decides → nut. Test in Task 1.
2. A result with only one leaf (e.g. only other flushes): the `Flush` row still appears with that single child. Test in Task 2.
3. A result with no flush: no `Flush` row at all. Covered by existing `test_hand_split_*` tests (Task 2 keeps them green).
4. Clicking the caret must not change the active pick or the hand list. Manual check in Task 3.
5. Re-running a spot after expanding: rows come back collapsed. Manual check in Task 3.
