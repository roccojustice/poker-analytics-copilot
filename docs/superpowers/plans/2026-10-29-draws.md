# Draws (M7 #7, part 4) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give every Spotlight hand a GTO Wizard draw type on the decision street, filterable and broken down by action, validated against PT4's draw flags.

**Architecture:** A pure `draws.py` classifier (like `hand_strength.py`) reusing `hand_strength` helpers; `spotlight.py` adds a `draw_type` column, a `draw_types` filter and a `draw_split`, mirroring the hand-type dimension; `api.py` passes them through; the page gets a Draw dropdown, a draw × action table and a third cumulative pick.

**Tech Stack:** Python 3, pandas, FastAPI, pytest, vanilla JS (`static/index.html`), Postgres (PT4).

**Spec:** `docs/superpowers/specs/2026-10-29-draws-design.md`

## Global Constraints

- Draw type names and order, verbatim: `"Combo draw", "Flush draw nuts", "Flush draw", "OESD", "Gutshot", "BDFD 2 cards", "BDFD 1 card", "No draw"`.
- Every hand on a river board → `"No draw"`; BDFD only on a 3-card board.
- GTO Wizard rules are authoritative; PT4 is the oracle only where it measures the same thing.
- Inline comments one line max; provenance goes to `docs/SCHEMA_NOTES.md`.
- Strict red-then-green TDD for every behavior change.
- `.env` points at `PT4_2026_10_29_075726` (the user's duplicate DB).

## Review Focus

1. Wheel draws (ace low): A♥5♥ on J♥8♥3♣2♠ is FD + gutshot (the 4) → `Combo draw`. Test in Task 1.
2. Board-only straights don't count: Hero's 2 on a 9-8-7-6 turn has no out (T / 5 make the board's straight). Test in Task 1.
3. Four-flush turn board: one hole card of the suit = made flush → no flush draw; no hole card of the suit → `No draw`. Test in Task 1.
4. Paired boards: a straight draw still counts with a pair on board (T9 on 8-8-J). Test in Task 1.
5. Bad card ids (0 / NaN) raise like `hand_type` does, never silently `No draw`. Test in Task 1.
